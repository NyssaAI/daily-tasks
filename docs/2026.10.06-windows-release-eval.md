## Blocking timestamp finding

The native reconciliation session read a saved JSON operation with PowerShell's
default `ConvertFrom-Json`, then reparsed the resulting value as a `DateTime` and
called `ToUniversalTime()`:

```powershell
$op = Get-Content $path -Raw | ConvertFrom-Json
$stamp = ([DateTime]::Parse($op.entry.recorded_at)).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ss.fffZ")
$op.entry.activity_at = $stamp
$op.entry.recorded_at = $stamp
```

The intended time was `2026-10-07T01:38:57.000Z`; the original persisted
`task.reconciled` event instead had `06:38:57.000Z` in both time fields. Event
`01a11402-d49c-7229-aeb3-e2d26d3c9024` remains immutable. The agent later appended
`01a11404-1d77-73e5-8c0e-45ecf5bd4bc8`, with `corrects` pointing to the original and
the intended time in its `after` object.

[Exact offending commands and correction output](../evals/results/2026-10-07T01-35-06-530Z-windows-native/timestamp-failure.json)
are retained. Independent `log-query` returns both original and correction; it
does not fold corrections into an effective event. A query for 06:00–07:00Z
[returns the wrong original event alone](../evals/results/2026-10-07T01-35-06-530Z-windows-native/incorrect-time-window-query.json).
This is a native workflow error, not a failing JSON parser or a reason to rewrite
append-only log history. Several creation cases also encountered temporary
culture-formatted timestamp validation failures and repaired their final records.

Recommended bounded repair: document PowerShell JSON handling in the maintained
CLI reference. Preserve returned ISO timestamps as strings through checkpoints,
Markdown and log payloads; use `ConvertFrom-Json -DateKind String` on supported
PowerShell, otherwise Node `JSON.parse`. Use `format-time` only for display and
avoid implicit stored-ISO `DateTime` reparsing. No log schema or correction-folding
change is needed to prevent this failure.

After repair, regenerate artifacts, review the delta, rerun deterministic checks,
and run fresh native timestamp-bearing mutations in all six scenario groups,
including the exact failed reconciliation and no-profile/shared-profile creation.
The shared CLI reference was loaded by all groups, so do not silently relabel this
candidate's native scores as current. Unchanged branch behavior can be cited as
prior evidence with its original candidate identity and dependency limits.
