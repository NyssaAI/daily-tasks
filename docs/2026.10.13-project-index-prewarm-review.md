## Scope and acceptance

Add a portable `warm-project-index` command that resolves the configured context
and invokes the existing stale-on-demand inventory operation without forcing a
refresh. Add a separate OpenClaw-native adapter that can optionally reconcile a
silent deterministic command automation during setup. The default interval is one
hour and is configurable. Scheduled execution must not start an agent or model.

Acceptance checks:

1. Every inventory consumer retains the existing stale-on-demand correctness path.
2. A cold warm rebuild writes the disposable cache; a fresh warm reuses it with zero
   source reads; edits, membership changes, TTL expiry, and date changes rebuild.
3. The portable command requires explicit vault scope, resolves the configured
   context independently of the process working directory, and emits one compact JSON
   result without the full inventory.
4. The OpenClaw adapter creates an exact-argv, no-delivery command automation with an
   idempotent declaration key, defaults to `1h`, and accepts a different interval.
5. Disabling or failing the schedule cannot make any consumer trust stale data.
6. Portable artifacts remain host-neutral; the native adapter is assembled separately.

## Findings

### DT-PREWARM-01 — Verified

- Requirement: add cheap optional prewarming without moving correctness into the
  scheduler.
- Baseline evidence: `projectInventory` already performs TTL, scope, local-date,
  membership, metadata, schema/rules, and cache-hash checks; no adapter or scheduled
  command exists.
- Consequence: first use after staleness pays rebuild cost, while no host integration
  can prewarm deterministically.
- Acceptance: the checks above pass against source and assembled artifacts.
- Evidence: source and assembled tests pass; isolated OpenClaw 2026.10.2 loaded
  the native adapter from its stable installed root, reconciled one command job,
  repeated setup without creating or updating a duplicate, rebuilt on the first
  run, reused with zero source reads on the second run, and rebuilt after a source
  metadata change while the schedule was disabled. The automation payload was an
  exact Node argv command with no agent turn and delivery mode `none`.
