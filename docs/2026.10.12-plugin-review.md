when its canonical owner differs from the configured user. Ownership and assignment
remain authoritative metadata; discovery does not reassign, start, or select work.

## Findings

### DT-OWNER-01 — Verified locally

- Evidence: `planningReview` filtered projects, tasks, selected rows, counts, and
  additions by exact equality with `userEmail`.
- Consequence: a valid inventory could contain open work while the planning review
  falsely displayed zero projects and zero tasks.
- Acceptance: a synthetic inventory whose owner differs from the profile still
  contributes to counts and available rows; selected other-owner work remains visible;
  owner/assignee metadata survives; invalid/ambiguous work remains gated.

### DT-OPS-02 — Verified locally and in an authorized live vault

- Evidence: planning preparation and maintenance treated every JSON file under
  `stateRoot/operations` as pending, including a retained legacy receipt with
  `status: completed` and a matching operation ID.
- Consequence: a completed 2026-10-05 operation forced every planning request into
  `recovery-required` and produced a false pending-operation maintenance diagnostic.
- Acceptance: both preparation and maintenance use one checkpoint classifier;
  completed legacy receipts are ignored, malformed/active checkpoints remain pending.

### DT-NAV-03 — Verified locally and in an authorized live vault

- Evidence: the navigation checker used `path.extname` for extensionless wiki links,
  so dotted date names such as `2026.10.07-note` were treated as already having an
  extension. Vault-relative links were also resolved only from the source directory.
- Consequence: maintenance reported 83 missing links, including present Markdown files.
- Acceptance: existing raw targets win; otherwise `.md` is tried regardless of dots,
  and an explicit vaultRoot enables vault-relative resolution. Live missing-link
  diagnostics fell from 83 to 3 actual missing resume attachments.

### DT-SCOPE-04 — Verified locally and in an authorized live vault

- Evidence: the planning skill already said to continue independent changes, but the
  test session summarized all maintenance findings as a global plan blocker.
- Consequence: unrelated legacy projects, missing baseline enrollment and navigation
  findings prevented a valid no-change rollover and review save.
- Acceptance: planning guidance now states explicitly that maintenance diagnostics are
  record/path scoped; only dependent writes pause.
