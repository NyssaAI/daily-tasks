## Findings and contract checks

**No actionable finding remains in this scoped repair.** The instruction change addresses the observed failure without requiring an incompatible clock change in the optimistic state-save protocol.

The initial `planning-prepare`/`resolve-context` omission of `now` matches `resolveContext`'s actual-clock default. The returned local day is calculated in the resolved timezone; UTC's calendar date is not substituted. `activity-time` independently defaults its recording time to the host clock, while a precise historical `reported` timestamp changes only activity time. The new prose explicitly excludes date-only requests and fixture/record/cache values as authority for a clock override.

The preparation-packet exception is necessary and correctly retained. `savePlanningState` re-prepares, compares inventory/review hashes and source/state hashes, then saves derived state. Reusing the packet's `context.now` preserves that derivation, including date-sensitive inventory behavior. A no-change rollover receipt intentionally uses that preparation clock through this API. The new rule requiring actual completion time applies to maintenance success, not an instruction to replace the packet clock during optimistic state save. The references still instruct reuse of `context.now` for both state actions.

Future selection uses a separate `date` with actual `today`, consistent with `planSelection` filtering active allocations relative to today and constructing the destination from date. It does not need a future instant. Rollover and future transfers retain stable event identities and timestamps for the same checkpoint, consistent with `operations.md`; the repair explicitly distinguishes a new decision after recovery, which needs a fresh activity-time result. Existing timestamp-string preservation rules remain intact.

Maintenance success now explicitly requires the actual GMT completion time after verification. This matches `maintenanceStatus`'s four-hour elapsed-time calculation and avoids immediately treating a just-completed pass as stale because of a copied historical seed.
