## Findings

### ADV-DT-001 — Medium — Ordinary directory navigation is rejected

**Maps to:** DT-NAV-05. **Affected:** shared navigation CLI and maintenance on all
packages; native host execution was not required to reproduce this library defect.

Expected: ordinary links to existing visible directories pass, while specific required
file evidence still needs a regular file. Observed: both Markdown [Outputs](outputs/)
and wiki [[outputs]] return invalid-link-target, Target is not a regular file, even
though outputs exists. A missing outputs/missing.pdf correctly returns
missing-link-target in the same fixture.

Evidence: lib/records/navigation.mjs:153–156 unconditionally requires isFile();
navigationLinks at :85–97 retains only target/wiki and carries no target-kind contract.
Probe: node .temp/plugin-review/probes.mjs, directory-navigation result, retained in
.temp/plugin-review/probes.log. This confirms the code defect independently, not the
lead's count of nine private links.

Acceptance: test Markdown/wiki directory navigation, actual file attachments, missing
files, directory-as-required-file evidence, directory fragments, unsafe/symlink targets
and receipt revalidation after target deletion/type change. Merely accepting every
isDirectory() target cannot satisfy the required-file boundary. Carry explicit observed
kinds through navigation receipts and freshness checks as appropriate.

### ADV-DT-002 — Medium — Worker evidence has no supported completion path

**Maps to:** DT-MAINT-06. **Affected:** portable maintenance integration and callers.
This is a documented implementation gap requiring repair or explicit disposition,
not evidence fabrication and not proof that planning itself globally blocks.

Expected under the repair acceptance: unavailable worker capability, inspection
freshness and trustworthy worker completion are distinguishable; independent planning
remains usable. Observed clean synthetic inspection succeeds and returns
successAdvanced:false. Immediate status returns inspectionDue:false together with
fullReconcileDue:true and trusted-worker-evidence-unavailable. There is no supported
worker-evidence ingestion path here; caller-supplied claims are explicitly rejected.

Evidence: lib/planning/maintenance.mjs:66–88; fresh-status and clean-inspection probe
results. planning-flow.md:86–108 already documents the gap and direct-check fallback;
:126–131 and daily-tasks-plan/SKILL.md:60–65 already prohibit a global stop. Do not
misdiagnose those existing safeguards as absent or convert CLI inspection to worker
success simply to make a Boolean false.

Acceptance: either implement trusted host-observed evidence with valid and invalid
fixtures, or explicitly expose/disposition unsupported capability independently of
freshness/due state. Test fresh/expired inspections, missing worker support, rejected
caller-authored claims, failed passes preserving old success, and independent planning
with unrelated diagnostics. If supporting trusted completion, demonstrate a real valid
completion as well as rejection cases; a reject-all interface is not implementation.

### ADV-DT-003 — Medium — Valid vault-relative targets make maintenance retry forever

**New adjacent regression. Affected:** shared maintenance/navigation integration.

Expected: an unchanged allowed navigation target elsewhere in the bound vault should
permit a successful CLI inspection and a fresh receipt. Observed: a managed project
links [[resources/evidence]] to an existing vault/resources/evidence.md. Navigation
returns diagnostics:[] and the correct target; maintenance throws
"Maintenance sources/state changed; retry" despite no concurrent change.

Evidence: navigation.mjs:133–135 permits vault-root fallback, but
maintenance.mjs:47 only allows projectsRoot/dailyPlansRoot when checking those same
targets. inspectMaintenance's final revalidation therefore always fails. The existing
navigation test called "outside the project collection" actually sets vaultRoot equal
to projectsRoot, so it does not exercise this boundary.

Probe: vault-navigation and vault-maintenance-error in .temp/plugin-review/probes.log;
fixture has distinct vaultRoot, projectsRoot and dailyPlansRoot. No record/view or
attachment changes occur between navigation and inspection.

Acceptance: distinct-root fixtures for vault resources with plain targets and heading
anchors must inspect successfully, stay fresh while unchanged, and become due after
deletion or heading edits. Preserve hidden-state, symlink and out-of-vault rejection.
Run this through both source and assembled CLI. Keep any directory-kind fix aligned
with the same target-validation contract (ADV-DT-001).

### ADV-DT-004 — High — Migration retirement misses supported vault-relative backlinks

**New adjacent regression. Affected:** migration-retirement, migration event validation
and migration-complete, which share inspectMigration.

Expected: every supported still-live backlink to a retiring DoD prevents retirement
until retargeted. Observed: a managed project index links
[[projects/alpha/definition-of-done]] to the retiring source. inspectNavigation resolves
it correctly with no diagnostic, yet inspectMigrationRetirement returns
allowed:true, issues:[]. Replacing just that link with [[definition-of-done]] produces
allowed:false/live-incoming-link. This is a false acceptance, not a missing-host gap.

Evidence: lib/operations/verification.mjs:264–270 resolves only relative to the source
file, plus a basename-only wiki heuristic; unlike navigation.mjs:133–135, no vault-root
candidate is considered. workspace-migration.md step 7 requires every still-live
incoming reference to verify before source retirement. A valid-looking retirement
response can therefore authorize deletion while leaving broken navigation.

Probe: relative-retirement, vault-relative-retirement and
vault-relative-retirement-navigation in .temp/plugin-review/probes.log. The synthetic
source/destination preserve the exact criterion UUID, checked state and narrative.
The positive control has the same operation and content; only backlink spelling
changes. No actual retirement or log append was needed to demonstrate the violation.

Acceptance: share consistent target resolution across navigation and retirement.
Cover vault-relative, file-relative, extensionless/dotted, encoded and heading forms
in project records and daily plans; all live links to the retiring file must refuse.
After retargeting, legitimate retirement must pass. Retest post-retirement event and
completion checks with an injected surviving backlink, preserving existing collision,
criterion/content, unrelated-edit and idempotent-recovery tests.
