# UC-02.03.01 Reconcile Manual Edits and Progress During Check-In

## Actor

Individual user checking in during the day after manually editing checkboxes or text in their daily plan or project files, or reporting verbal progress.

## Goal

Reconcile manual document edits and spoken progress updates with canonical project records, resolve any state discrepancies or unmet completion criteria, and keep today's daily plan accurate.

## Starting Context

The user has an existing vault with project records and (optionally) a daily plan for today or a prior day, and may have edited checkboxes or notes directly in a text editor (see [C-01: Canonical Work Records & Embedded Definition of Done](../../concepts/c-01-canonical-work-records.md) and [C-02: Local-Day Plan, Rollover & Carried Selections](../../concepts/c-02-local-day-plan-and-rollover.md)).

## Entry Route

The user asks to check in, report progress, reconcile manual edits, or resume an interrupted check-in.

## Trigger

The user invokes the check-in workflow.

## Process

```text
User checks in and reconciles manual edits and progress
+-- Starting context: User has edited daily plan or project files manually or reports progress in chat
+-- Entry route: User asks to check in or resume an interrupted check-in
+-- Trigger: Check-in workflow starts
+-- Step 1: System compares current daily plan and project files against canonical record states and prior baseline
|   +-- Today's daily plan is missing: System prepares today's plan with carried-forward unfinished selections (↺)
|   +-- Unresolved interrupted check-in exists: System offers to resume from the saved checkpoint
|   \-- Manual checkbox or state differences detected: System identifies each discrepancy for review
+-- Step 2: System evaluates manual completions and reported progress against completion rules
|   +-- Task checked complete manually and all Definition of Done items and blockers are satisfied: System proposes propagating completion to the canonical task record
|   +-- Task checked complete manually but DoD items or blockers remain open: System flags the conflict and asks whether to check the remaining criteria, resolve the blocker, or keep the task in progress
|   \-- Unlinked manual line added to daily plan: System offers to capture it as a candidate task or keep it as a personal note
+-- Step 3: User adjudicates conflicts and confirms progress updates
+-- Step 4: System non-destructively updates canonical records, refreshes today's daily plan, and logs all decisions
\-- Success: Canonical records and today's daily plan are synchronized with all user notes preserved
```

## Step Details

### Step 2: System evaluates manual completions and reported progress against completion rules

Checking a task box in a daily plan does not silently bypass Definition of Done or blocker rules on the underlying task record; if criteria are still unchecked, the check-in surfaces them explicitly for the user to decide.

## Success

Manual edits and reported progress are reconciled cleanly between the daily plan and canonical project records, conflicts are resolved by the user, and decisions are logged.

## Failure Cases

- Corrupted or missing reference ID on a modified row: System suspends automatic mutation for the affected item, preserves the user's text verbatim, and asks the user how to link or resolve it.
- Interrupted check-in session: State is preserved so the user can resume without repeating earlier decisions.
