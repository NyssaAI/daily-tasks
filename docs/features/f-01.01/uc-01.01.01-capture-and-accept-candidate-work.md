# UC-01.01.01 Capture and Adjudicate Candidate Work

## Actor

Individual user extracting potential commitments from meeting notes, messages, or rough ideas.

## Goal

Review candidate projects, milestones, and tasks extracted from unstructured text, check for duplicates against existing work, and explicitly accept, edit, or reject each item before any record is created.

## Starting Context

The user has unstructured notes, messages, or quoted requests that may contain action items (see [C-03: Explicit Adjudication & Decision Log](../../concepts/c-03-explicit-adjudication-and-decision-log.md)).

## Entry Route

The user pastes notes, references a document or conversation, and asks the assistant to capture possible tasks or extract action items.

## Trigger

The user asks to extract or review candidate work from supplied content.

## Process

```text
User captures and adjudicates candidate work
+-- Starting context: User supplies notes, messages, or rough ideas alongside existing vault records
+-- Entry route: User asks to capture or extract possible work
+-- Trigger: Candidate capture workflow starts
+-- Step 1: System extracts candidate items and compares them against existing projects, milestones, and tasks
|   +-- Potential duplicate found: System flags the matching existing record alongside the candidate
|   \-- Net-new candidate found: System proposes target project, milestone, title, and details
+-- Step 2: System presents a numbered list of candidates waiting for explicit user decision
+-- Step 3: User replies with individual or batch decisions (accept, edit, or reject)
|   +-- User accepts or edits a candidate: System hands the approved item to record management for creation
|   +-- User rejects a candidate: System discards the candidate and records the rejection decision
|   \-- User supplies bare numbers or leaves items unanswered: System asks for clarification and creates nothing for unanswered items
\-- Success: Only explicitly accepted candidates are created as canonical work records and logged
```

## Step Details

### Step 1: System extracts candidate items and compares them against existing projects, milestones, and tasks

Quoted requests, inferred promises, and rough notes never bypass candidate review. By contrast, when a user directly instructs the assistant to create a specific named task or project, that direct instruction already supplies acceptance and goes straight to record creation.

## Success

Accepted candidates are created as canonical project, milestone, or task records with logged decisions, duplicate work is avoided, and rejected or unanswered candidates never pollute active project records.

## Failure Cases

- Ambiguous or bare-number reply: System prompts the user to specify whether to accept, edit, or reject the numbered candidates before creating any files.
- Missing parent project or milestone for an accepted task: System asks which project and milestone the task belongs to before writing the record.
- Unwritable vault or missing setup: System offers the extracted candidate proposal in chat and reports that file persistence requires vault setup.
