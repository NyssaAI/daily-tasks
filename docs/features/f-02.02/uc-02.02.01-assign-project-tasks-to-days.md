# UC-02.02.01 Assign Open Project Tasks & Blockers to Days on Screen 2

## Actor

Individual user stepping through open projects during a daily planning session.

## Goal

Review open projects one at a time, assign plannable tasks and blocker follow-ups to today or future dates, delegate work, and update statuses using stable session-wide row numbers.

## Starting Context

The user has reviewed Screen 1 ([UC-02.01.01](../f-02.01/uc-02.01.01-review-and-adjudicate-message-suggestions.md)) and replied `"yes"` to review open projects and tasks (Stage 2 of [C-04: Three-Screen Planning Session Macro-Flow](../../concepts/c-04-three-screen-planning-session.md)).

## Entry Route

The user advances from Screen 1 to **Screen 2 (Assign Tasks to Days)**, or returns to a project on Screen 2 from the Screen 3 recap.

## Trigger

The user enters Screen 2 or navigates between projects (`"next"`, `"previous"`).

## Process

```text
User assigns open project tasks and blockers to days on Screen 2
+-- Starting context: Open projects ordered with unplanned eligible work first; session row numbering continues from Screen 1
+-- Entry route: User replies "yes" on Screen 1 or navigates between projects on Screen 2
+-- Trigger: Screen 2 renders for the current project (Project k of M)
+-- Step 1: System displays the project's milestone outline, plannable milestone task tables, and open blockers with continuous row numbers
|   +-- User toggles milestone scope ("only M2" vs. "include in-progress milestones"): Screen updates visible plannable milestones
|   \-- Tasks remain numbered fixed for the entire session across projects and refreshes
+-- Step 2: User issues batch commands by row number or milestone label
|   +-- Day assignment ("14 today", "13 tomorrow", "16 Friday", "17 unplan", "18 today"): System updates each item's single active planned day
|   +-- Delegation ("assign 14 to alex@example.com", "18 owner dana@example.com"): System updates task assignee or blocker owner
|   +-- Status or blocker change ("12 done", "M2 complete", "18 resolved", "13 blocked on legal"): System checks completion rules and updates state
|   \-- Bare list of numbers or invalid constraint: System refuses the batch and explains what is missing
+-- Step 3: User navigates across projects or finishes project review
|   +-- User replies "next" or "previous": System displays the adjacent project on Screen 2
|   \-- User replies "finish" (or "yes" on the last project): System transitions to Screen 3 (Confirm Today's Plan)
\-- Success: Planned days, assignments, and status updates across projects are staged and ready for final recap on Screen 3
```

## Step Details

### Step 1: System displays the project's milestone outline, plannable milestone task tables, and open blockers

Projects with unplanned eligible work appear first. Within a project, the lowest incomplete milestone is always plannable, and other in-progress milestones can be shown or hidden on command. Row numbers continue monotonically from Screen 1 so a number always identifies the exact same task or blocker throughout the session.

### Step 2: User issues batch commands by row number or milestone label

Choosing a new planned day moves the item's active planned day (`Today`, a future date, or `—`) without changing its target due date (see [C-02: Local-Day Plan, Rollover & Carried Selections](../../concepts/c-02-local-day-plan-and-rollover.md)). Blocked tasks carry a `⛔` warning indicator but can still be planned.

## Success

The user has assigned desired tasks and blocker follow-ups to today or future days across open projects, all changes are staged with decision log entries, and the session advances to Screen 3.

## Failure Cases

- Marking a task done with unchecked Definition of Done items or open blockers: System refuses the status change and reports which criteria or blockers remain open.
- Completing or cancelling a milestone with open child tasks: System requires an explicit decision for each open child task.
- Bare row numbers without an action: System prompts the user to clarify whether they want to plan those rows for today, change their status, or assign them.
