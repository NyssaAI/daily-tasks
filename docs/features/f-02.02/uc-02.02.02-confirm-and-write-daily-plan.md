# UC-02.02.02 Review Recap and Confirm Today's Plan on Screen 3

## Actor

Individual user completing a daily planning session.

## Goal

Review the final recap of today's personal work, delegated work, and active blockers on Screen 3, make any last-minute adjustments, and confirm the plan to write today's daily plan document and staged record changes atomically.

## Starting Context

The user has completed project review on Screen 2 ([UC-02.02.01](uc-02.02.01-assign-project-tasks-to-days.md)) and moved to **Screen 3 (Confirm Today's Plan)** (Stage 3 and Stage 4 of [C-04: Three-Screen Planning Session Macro-Flow](../../concepts/c-04-three-screen-planning-session.md)).

## Entry Route

The user replies `"finish"` on Screen 2 or `"yes"` on the final project of Screen 2.

## Trigger

Screen 3 is displayed with today's planned selections.

## Process

```text
User reviews Screen 3 recap and confirms today's plan
+-- Starting context: Tasks and blockers planned for today are staged in the session
+-- Entry route: User finishes Screen 2 project review
+-- Trigger: Screen 3 recap is rendered
+-- Step 1: System displays today's counts (Planned today, Mine, Delegated, Late) and restarts row numbering at 1
|   +-- My work table: Lists tasks planned for today assigned to the user
|   +-- Delegated work table: Lists tasks planned for today owned by the user and assigned to others
|   +-- Blockers table: Lists open blockers affecting today's tasks or scheduled for follow-up today
|   \-- Pending suggestions warning: Notes any unanswered suggestions from Screen 1 that will stay pending for next session
+-- Step 2: User optionally makes small recap edits or navigates back
|   +-- Small edit ("Remove 3 from today", "Move 2 to tomorrow", "1 done", "6 resolved"): System updates recap and renumbers Screen 3 rows
|   +-- Stale row number from Screen 1 or 2 used: System rejects the stale number and asks the user to use Screen 3's row numbers
|   \-- User asks to return to a project ("Back to Cloud Sync"): System returns to Screen 2 and restores session row numbers
+-- Step 3: User replies "Confirm" to finalize the plan
|   +-- Underlying files unchanged since session start: System atomically writes staged record changes, appends decision log entries, updates message cursors, and writes YYYY.MM.DD-daily-plan.md
|   \-- External file edit detected on disk: System refuses the write to protect manual edits and prompts for reconciliation
\-- Success: Today's daily plan document and all adjudicated record updates are persisted on disk and the session closes as confirmed
```

## Step Details

### Step 1: System displays today's counts and restarts row numbering at 1

Screen 3 shows only items planned for today plus open blockers on those tasks. Row numbering restarts at `1` specifically for the recap screen; row numbers from Screens 1 and 2 are not accepted while on Screen 3 so accidental cross-screen edits cannot occur.

### Step 3: User replies "Confirm" to finalize the plan

Unanswered suggestions do not block confirming; they remain in the pending suggestions buffer and their source messages stay unreviewed so they are offered again in the next session.

## Success

`YYYY.MM.DD-daily-plan.md` is written using the user's active daily plan template, all staged task/milestone/blocker edits and decision log entries are saved atomically, and the planning session completes.

## Failure Cases

- Stale row number from Screen 1 or 2 supplied on Screen 3: System refuses the command and reminds the user that Screen 3 uses its own `1..N` numbering.
- Concurrent manual modification of a record file during the session: System aborts the atomic commit so no external edit is lost and guides the user to reconcile.
- User cancels the session instead of confirming: All staged changes are discarded cleanly and no disk files are modified.
