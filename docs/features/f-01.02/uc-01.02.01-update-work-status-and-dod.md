# UC-01.02.01 Update Task Status, Definition of Done & Blockers

## Actor

Individual user managing active projects, milestones, tasks, and external blockers.

## Goal

Create named work or update task progress, Definition of Done criteria, delegation, dependencies, and blockers while enforcing completion guardrails and preserving user notes.

## Starting Context

Canonical project, milestone, task, and blocker records exist in the workspace (see [C-01: Canonical Work Records & Embedded Definition of Done](../../concepts/c-01-canonical-work-records.md)).

## Entry Route

The user directly asks the assistant to create named work, mark a task or checklist item done, reassign a task, or add/resolve a blocker, or issues a record update command during planning or check-in.

## Trigger

The user instructs the system to create or modify a project, milestone, task, or blocker record.

## Process

```text
User creates or updates canonical work records
+-- Starting context: Existing workspace records with embedded Definitions of Done and blocker links
+-- Entry route: Direct record instruction or planning/check-in update command
+-- Trigger: User specifies a create or update action
+-- Step 1: System locates the target record and validates the requested change against domain rules
|   +-- User marks a task completed: System checks that all Definition of Done items are done and no open blockers remain
|   |   +-- All criteria met: Transition to completed is approved
|   |   \-- Unchecked DoD items or open blockers exist: System refuses completion and lists what is still missing
|   +-- User marks a milestone completed or cancelled: System verifies all child tasks are finished or have explicit decisions
|   \-- User updates assignee, target date, DoD checkbox, or blocker state: System validates target references
+-- Step 2: System surgically updates the affected record files and parent index tables
+-- Step 3: System appends the change and user attribution to the decision log
\-- Success: Canonical records reflect the validated update with all user prose and formatting preserved
```

## Step Details

### Step 2: System surgically updates the affected record files and parent index tables

Only the changed metadata fields, status markers, and checklist boxes are updated in the document. All user-written paragraphs, comments, and layout spacing remain untouched.

## Success

The target project, milestone, task, or blocker record and its parent summary tables are updated accurately, completion guardrails are enforced, and an audit entry is appended to the decision log.

## Failure Cases

- Task marked done with incomplete Definition of Done or open blocker: System refuses the transition and tells the user which checklist items or blockers must be resolved first.
- Milestone closed while child tasks are still open: System prompts the user for an explicit decision on each open task rather than cascading status changes silently.
- External file conflict: System detects that the record file was modified concurrently and asks to reconcile before overwriting.
