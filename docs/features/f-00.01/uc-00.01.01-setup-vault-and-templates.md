# UC-00.01.01 Set Up Vault, Identity & Templates

## Actor

Individual user setting up Daily Tasks for the first time or updating personal and vault preferences.

## Goal

Establish personal identity, local timezone, priorities, vault folder paths, and document template preferences so work records and daily plans are maintained and formatted predictably.

## Starting Context

The user has a local or shared knowledge vault (PARA or plain folder) where they want to manage projects and daily plans, or wants to update their existing profile settings (see [C-01: Canonical Work Records & Embedded Definition of Done](../../concepts/c-01-canonical-work-records.md)).

## Entry Route

The user asks the assistant to set up Daily Tasks, change their timezone or priorities, or customize a document template, or triggers a Daily Tasks workflow when profile settings are not yet configured.

## Trigger

The user requests vault setup or preference updates, or invokes a workflow that detects missing identity or vault bindings.

## Process

```text
User configures identity, vault locations, and templates
+-- Starting context: New vault or existing profile needing updates
+-- Entry route: User asks to set up or update Daily Tasks preferences
+-- Trigger: Setup request or first-time workflow invocation
+-- Step 1: Assistant checks existing personal and vault profile settings
|   +-- Existing settings found: Assistant reuses known values and asks only for missing or requested changes
|   \-- First-time setup: Assistant prompts for name, email, local timezone, and vault folders
+-- Step 2: User confirms vault folders for projects and daily plans
|   +-- PARA or plain folder selected: Assistant defaults to 1-projects and 2-areas/daily-plans unless customized
|   \-- Invalid, unreachable, or agent-runtime path provided: Assistant explains the issue and asks for a valid vault location
+-- Step 3: User optionally supplies custom templates or selects a template update policy
|   +-- Custom example or template provided: Assistant registers the layout for future records of that kind
|   \-- Bundled template updated: Assistant previews layout changes and asks whether to adopt, keep current, or decide later
\-- Success: Personal and vault preferences are saved in user configuration and ready for record and planning workflows
```

## Step Details

### Step 1: Assistant checks existing personal and vault profile settings

Personal settings (name, email, timezone, personal priorities) are kept separate from per-vault folder bindings in `~/.nyssa-ai/daily-tasks/` so the user does not have to re-enter identity details when working in another vault, and zero `.nyssa-ai/` files are placed inside the vault.

### Step 3: User optionally supplies custom templates or selects a template update policy

Each document kind (project, milestone, task, blocker, and daily plan) can be customized independently. Existing work records are never reformatted automatically unless the user explicitly asks to reformat them.

## Success

The user's identity, local timezone, priorities, vault folder paths, and template preferences are saved and confirmed, and subsequent workflows reuse them automatically without re-prompting.

## Failure Cases

- Missing email or unresolvable timezone: Assistant explains which identity detail is missing and asks the user to supply it before saving.
- Unwritable, invalid, or agent-persona runtime path passed as vault: Assistant reports why the chosen folder cannot serve as a vault and asks for clarification without creating partial files.
- Intervening manual edits on an active template during upgrade: Assistant detects the user's edits and asks for confirmation before replacing the template layout.
