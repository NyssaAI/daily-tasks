# UC-00.01.01 Set Up Workspace, Identity & Templates

## Actor

Individual user setting up Daily Tasks for the first time or updating personal and workspace preferences.

## Goal

Establish personal identity, local timezone, priorities, workspace storage folders, and document template preferences so work records and daily plans are stored and formatted predictably.

## Starting Context

The user has a local folder or knowledge vault where they want to manage projects and daily plans, or wants to update their existing profile settings (see [C-01: Canonical Work Records & Embedded Definition of Done](../../concepts/c-01-canonical-work-records.md)).

## Entry Route

The user asks the assistant to set up Daily Tasks, change their timezone or priorities, or customize a document template, or triggers a Daily Tasks workflow when profile settings are not yet configured.

## Trigger

The user requests workspace setup or preference updates, or invokes a workflow that detects missing identity or workspace bindings.

## Process

```text
User configures identity, workspace locations, and templates
+-- Starting context: New workspace or existing profile needing updates
+-- Entry route: User asks to set up or update Daily Tasks preferences
+-- Trigger: Setup request or first-time workflow invocation
+-- Step 1: Assistant checks existing personal and workspace profile settings
|   +-- Existing settings found: Assistant reuses known values and asks only for missing or requested changes
|   \-- First-time setup: Assistant prompts for name, email, local timezone, and workspace folders
+-- Step 2: User confirms workspace folders for projects and daily plans
|   +-- Existing knowledge vault layout detected: Assistant offers existing project and daily plan folders
|   +-- Plain folder selected: Assistant offers standard projects and daily-plans folders without creating extra vault folders
|   \-- Invalid or unreachable path provided: Assistant explains the issue and asks for a valid location
+-- Step 3: User optionally supplies custom templates or selects a template update policy
|   +-- Custom example or template provided: Assistant registers the layout for future records of that type
|   \--Bundled template updated: Assistant previews layout changes and asks whether to adopt, keep current, or decide later
\-- Success: Personal and workspace preferences are saved and ready for record and planning workflows
```

## Step Details

### Step 1: Assistant checks existing personal and workspace profile settings

Personal settings (name, email, timezone, personal priorities) are kept separate from workspace folder bindings so the user does not have to re-enter identity details when working in a known workspace.

### Step 3: User optionally supplies custom templates or selects a template update policy

Each document kind (project, milestone, task, daily plan, and planning screen) can be customized independently. Existing work records are never reformatted automatically unless the user explicitly asks to reformat them.

## Success

The user's identity, local timezone, priorities, workspace storage paths, and template preferences are stored and confirmed, and subsequent workflows reuse them automatically without re-prompting.

## Failure Cases

- Missing email or unresolvable timezone: Assistant explains which identity detail is missing and asks the user to supply it before saving.
- Unwritable or invalid workspace path: Assistant reports that the chosen folder cannot be accessed and asks for clarification without creating partial files.
- Intervening manual edits on an active template during upgrade: Assistant detects the user's edits and asks for confirmation before replacing the template layout.
