# UC-03.02.01 Run Interactive Planning Session Through Assistant Tool Service

## Actor

Calling AI assistant acting on behalf of the user during a daily planning session.

## Goal

Drive the three-screen daily planning session through structured tool calls that enforce stage ordering, validate user verdicts and operations, keep diagnostic logs separate from tool responses, and persist changes only upon confirmation.

## Starting Context

The user's AI assistant is connected to the Daily Tasks planning session tool service with a configured vault (see [C-04: Three-Screen Planning Session Macro-Flow](../../concepts/c-04-three-screen-planning-session.md)).

## Entry Route

The user asks their AI assistant to plan the day, prompting the assistant to invoke the planning session tools.

## Trigger

The assistant calls the session start tool for today's date.

## Process

```text
Assistant drives a planning session through the tool service
+-- Starting context: Assistant host connected to the Daily Tasks planning tool service
+-- Entry route: User asks the assistant to plan the day
+-- Trigger: Assistant invokes start-session tool
+-- Step 1: Tool service loads vault records, correlates unread messages, and returns Screen 1 with a session ID
|   +-- Vault configuration valid: Returns Screen 1 markdown and session state
|   \-- Missing vault or user settings: Refuses startup with clear configuration guidance on diagnostic output
+-- Step 2: Assistant translates user replies into structured suggestion verdicts and planning operations
|   +-- Valid verdicts/operations for current screen: Service updates in-memory session state and returns refreshed screen
|   +-- Out-of-stage tool call (e.g., confirming before Screen 3): Service returns a refused response naming the expected next tool
|   \-- Validation error in batch: Service returns an error/refused response leaving session state unchanged
+-- Step 3: Assistant advances across Screen 1 -> Screen 2 -> Screen 3 as directed by the user
+-- Step 4: Upon user confirmation on Screen 3, assistant calls confirm-plan tool (or cancel-session if user aborts)
|   +-- Confirm called on Screen 3: Service atomically writes staged record changes, decision log entries, cursors, and daily plan
|   \-- Cancel called at any active stage: Service discards the session without modifying any files
\-- Success: Assistant presents the confirmed daily plan path and summary to the user
```

## Step Details

### Step 2: Assistant translates user replies into structured suggestion verdicts and planning operations

The assistant handles natural-language interpretation of the user's reply, while the tool service deterministically validates row numbers, stage rules, and completion constraints before staging any change. All diagnostic logs are emitted to a separate diagnostic stream so structured tool responses remain uncorrupted.

## Success

The assistant completes or cancels the multi-turn planning session reliably, presenting validated screens at each turn and persisting changes only after the user confirms on Screen 3.

## Failure Cases

- Tool called in the wrong session stage: Service returns a `refused` status naming the current stage and the expected next tool call.
- Unknown or expired session ID: Service returns a not-found error instructing the assistant to start a new session.
- Planning requested for a date other than today: Service refuses the date with a validation message stating that only today's local date can be planned in a live session.
