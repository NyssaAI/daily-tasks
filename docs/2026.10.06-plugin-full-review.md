- **#1:** Rename a canonical record to `task.MD`: inventory's case-insensitive scan includes it, but `inspect-records` uses `endsWith('.md')` and omits it. Inspection can miss an entire project or report its referenced records missing. Use the same case-insensitive extension policy and test membership parity across both commands. **Confirmed from source; actual incidence was not measured.**
- **#2:** The verifier requires exactly five scenarios, while the evaluation guide requires a sixth, configuration discovery and direct acceptance. A synthetic workflow-v2 receipt passed with five; adding `configuration-discovery` caused `Incomplete scenario inventory`. Release evidence can therefore miss existing-profile/output-location regressions. Add a stable sixth ID and an independently specified regression fixture proving five fails and six passes.
- **#3:** With project order First -> Second and First's state mistyped, inventory filters First out. The planning review then offers Second's task without an all-milestones request. The reproduced `invalid-state` diagnostic only marks the screen incomplete. Preserve the invalid milestone's project/sequence barrier and withhold affected later additions until ordering is resolved; retain unrelated projects and existing selections.
- **#4:** A profile with sibling vault, home and projects directories resolves as `configured:true`, then inventory throws `Inventory scope must be portable beneath vaultRoot or homeRoot`. Ordinary planning fails for storage the profile contract accepts. Choose a stable non-absolute external-root scope identifier, retain relative record paths and the resolved-root cache binding, and test resolver-to-inventory behavior with independent roots. Two reviewers agreed; the validator reproduced it.
- **#5:** A checklist row followed by an indented hidden `ref` comment keeps its UUID in `parseRecord`, but the reproduced `parseChecklist` result has `id:null, candidate:true`. Carry-forward becomes unresolved; an unidentified active selection can suppress all additions. Associate next-line references with their preceding list rows consistently, then test both parsers and inventory with same-line and next-line forms.
- **#6:** An unchecked, struck-through `Cancelled` row in a future plan sets `cancelled:true` without `state:'cancelled'`. Against an open canonical task, the reproduced result has no diagnostic, no allocation, and the task available today. Normalize the supported legacy form in both projection parsers so reconciliation catches the state difference before planning; preserve `checked:false` and test daily-plan and project-view edits.
- **#7:** Monday has unfinished selected A; explicit future selection pre-creates Tuesday with B. Tuesday's existing-plan branch skips prior-plan discovery, so A is omitted and loses later continuity. Run rollover once per local day regardless of file existence, merge by UUID, preserve B, explicit removals and other future allocations, and record completion only after verified persistence. Align the skill and screen, regenerate packages, and verify both Monday-A/Tuesday-B and repeat Tuesday after removing A. **Confirmed from the prescribed workflow; native-host incidence was not measured.**
